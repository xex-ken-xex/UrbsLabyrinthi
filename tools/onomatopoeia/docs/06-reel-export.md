# リール(縦の短い動画)向けの書き出し

ken 2026-10-19「拡散したいのでリールで使える形式で出力する機能が入れられるか検討して。すごい短いのを映像間に挟むような使い方」「透過色をつけられて、アニメーション画像、キャンバスサイズ指定」。

## 入れたもの(実験室の「書き出し」の欄)
- **大きさ**: 幅と高さを自由に(目安の選択: 1080×1920 リール、1080×1080、1920×1080、540×960)。
- **拡大**: ゲームの「×2」と同じ尺度。1080 幅なら ×6 で 14px の字が 84px。
- **背景**: 透過 / 緑・青(クロマキー)/ 黒 / 白 / 舞台と同じ / 色を選ぶ。
- **fps**: 30 / 60 / 24 / 15。**前後の間**: 最初と最後に足す秒数。**発生点をまとめて中央に**: 置いた発生点の重心を画面の中央へ。
- **APNG**(透過のアニメ画像。拡張子は .png のまま。`cue_export.js` の `apng()`: 各コマの PNG を fcTL / fdAT に組み直すだけで、外部ライブラリなし)
- **PNG 連番(zip)**(透過。編集ソフトに入れるならこれが確実。zip は無圧縮の最小形)
- **WebM**(動画。`MediaRecorder` + `canvas.captureStream`。**透過は残らない**ので背景を緑にしてクロマキーで抜く。VP9)
- **1コマ見る**: いまの時刻の 1 コマを市松の上に出して、透過と大きさを確かめる。

## 確かめたこと(2026-10-19、Chromium で)
- 540×960・30fps・ギンッ!(slam)で、APNG 45 コマ 1.0 MB、PNG 連番 45 枚 1.0 MB、WebM 1.5 秒 0.1 MB。APNG は Python の Pillow で 45 コマ・RGBA と読めた。WebM は ffprobe で vp9 540×960。
- 1080×1920 では APNG が数 MB になる(透過の文字だけなので圧縮は効く)。

## 使い方の案(リールに挟む)
1. 発生点を 1〜2 個置き、拡大 ×6〜8、1080×1920、背景「透過」で **PNG 連番** を書き出す。
2. 編集ソフト(CapCut、Premiere、DaVinci など)に連番として読み込み、映像の間に 0.5〜1.5 秒だけ重ねる。
3. 透過が読み込めないソフトなら、背景を緑にした WebM をクロマキーで抜く。
4. Instagram のリールは 1080×1920、30fps が推奨。mp4 は出す側で変換する(ブラウザからは直接 mp4 を作れない)。

## 入れなかったもの・課題
- **GIF**: 透過が 1 ビットで縁がぎざぎざになり、256 色。APNG で足りるので入れていない。要るなら減色の処理を足す。
- **mp4(H.264)**: ブラウザの `MediaRecorder` では作れない(Safari の一部を除く)。WebM を変換するか、`WebCodecs` + mp4 の多重化のライブラリが要る。
- **透過つきの動画(VP9 alpha / ProRes 4444)**: `MediaRecorder` では出せない。連番で代える。
- WebM は実時間で録るので、長い擬音や重い端末では落ちるコマがある。APNG / 連番はコマごとに描くので正確。
- 発生点の印(丸)と床の格子は書き出さない。擬音の文字だけ。
