# ダンジョンの広さと、冒険者の食い扶持

## 1. 問い

> 年に2,000人もの冒険者が来る迷宮で、この狭さで、食い扶持が稼げるか。特に上層は、冒険者が多いのでは。

結論: **狭すぎた。** 旧い層(56×38マス)は、都市資料の人数を支えられない。層ごとに広げ、上の層ほど広くした。

## 2. 都市資料の数字

| 項目 | 値 | 出典 |
|---|---|---|
| 登録冒険者 | 約3,000人(灰408、青銅1,360、銀980、黒鉄495) | players §14.4、§15.2、GM §15 |
| 毎年の新規 | 約2,000人。大半が1年以内に辞めるか死ぬ | players §14.4 |
| 迷宮での死者 | 年に1,000人前後 | players §14.4 |
| 燐晶(原料)の取引額 | 年 約600万銀貨 | GM §14.2 |
| 燐晶(精錬)の輸出量 | 年 約110t、80銀貨/kg | GM §14.1 |
| 冒険者の年収の目安 | 約2,830銀貨 | spec §9 |
| 浅層の燐晶 | 尽きかけている(査定が、少しずつ上がっている) | players §10、GM §10 |

## 3. 見積もり

- 原料の取引額 600万銀貨 ÷ 3,000人 = **1人あたり年 約2,000銀貨**(税の前)。1日あたりでは、都市全体で **約16,400銀貨**。
- 潜るのは、3日に1回とする(休み、治療、装備の手入れ)。1日に潜る人は約1,000人 = **約250パーティ**(4人組)。
- 1パーティの1回の潜行で、燐晶は、約67銀貨ぶん(低純度なら 約2.2kg)。

### 旧い広さ(56×38マス)の場合

- 56×38 = 2,128マス。1マス5フィートなので、約85m × 58m。部屋は13、宝のある部屋は、第1層で3つ(宝は 60銀貨ぶん)。
- 都市が1日に必要な16,400銀貨は、この区画の宝の **270回ぶん**。約250パーティが、一つの区画の宝を取り合うことになり、数パーティで尽きる。
- つまり、「区画」として作った地図を、「層全体」のように扱っていたのが、狭さの原因。

## 4. 方針

1. **層は、階のグループ。** 第N層は、1〜5階からなる(階は、階段でつながった1枚の地図)。層は、浅いほど階が多い。全体で30階、深さ約200m(30〜40階建てのビルほど。ken 2026-10-17)。
2. **地図は「区画」。** 迷宮の1階は、とてつもなく広い。ゲームの1日は、その中の1区画(巣の集まる、ギルドが案内する一帯)に潜る。区画は夜ごとに作り直される(通路が毎夜組み替わる)。【案】
3. **上の層ほど広く、薄い。** 上の層は、全員が通り、新人の灰が毎年2,000人流れ込み、闇潜りも多い。浅層は燐晶が尽きかけていて、低純度。深い層ほど、狭く、濃く、強い。
4. **魔物の数は、縄張りで決める。** 広くしても、魔物を詰め込めば、魔物同士が争う。巣の間隔と、密度の係数を、層ごとに決めた(docs/dungeon-ecology.md)。
5. **混み具合を、床で見せる。** 遺体は、広さに比例して置かれ、上の層ほど多い。

層ごとの階の数、広さ、高さ、魔物の密度(`density`)は、生成器のワイヤフレーム `Core.WIRE`(`docs/urbs-labyrinthi.html`)が持つ。
「魔物(1階)」と「燐晶 kg(1階)」の目安は、燐の循環の数理モデル `node tools/dungeon-model.mjs --json` の値(`docs/dungeon-model.md` §7)。
地図を作り直すには `node tools/export-floors.mjs`(階のファイルは gzip して `godot/data/floors/` に置く)、確かめるには `node tools/check-floors.mjs`(魔物の数は、7夜の平均が目安の ±40% に入ること)。
燐晶 kg の目安は、宝と落とし物と露頭と遺体を合わせた Godot 側の数なので、生成器の宝だけでは届かない(合わせるのは、燐の流れの PR)。

### 5.1 全階で同じもの(ワイヤフレーム)

- **縦穴**: 全階の中央に 20m四方(13×13マス)の虚空(`O`)。歩けないが見通せる。縁に幅1マスの回廊。底は真っ黒。
- **階段の候補地**: 縦穴を囲む半径26マスの七角形に7つ。上り階段は候補地 mirror(夜+階−1)、下り階段は mirror(夜+階)(子守唄の息継ぎの数だけ巡る。都市 GM 資料 §12.4)。だから、下の階の上り階段はこの階の下り階段の真下にあり、今夜の下りが明日の上りになる。
- **竪坑**: 第1〜6層に4本。2×2 の穴と、まわりの小部屋。第6層のいちばん下の階だけ穴がなく、上から落ちてきた物が溜まる。
- **骨組み**: 縦穴の縁の回廊、骨組みの道、大部屋。基礎の種で決まり、夜をまたいで変わらない。腐葉は洞窟(放射・環・外の道、灯守の灯)、錆鉄は 16マスおきの主坑道の格子。水鏡・骨・螺旋の骨組みは、あと。
- **一画**: 骨組みで囲まれた岩を 24マスの升目で区切ったもの。通路と小部屋は一画の中だけで作り、静かな夜は4割、吐く夜は全部が組み替わる。組み替わらない一画は、前の夜と同じ(隣が替わっても変わらない)。

## 6. ゲームの数字との関係

- 地図の宝の量は、卓の単位。ゲームでは、宝の量(kg)に `Balance.CRYSTAL_SCALE`(いま 0.3)をかけて置く。
- 都市資料の「1パーティの1回の潜行 約67銀貨」と比べると、区画の掃除は、**数回ぶんの長い遠征**と読める。短い潜行と区画の掃除は、遊び方の違い。
- 値は、遊んで直す。`CRYSTAL_SCALE` を上げれば、稼ぎが増える。

## 7. 描画と処理

- 床の描画は、**画面に入るマスだけ**。
- 魔物は、仲間から 520px(約16マス)より遠いものを、押し合いの計算から外した。押し合いは、x の順に並べて、遠い組を調べない。魔物の視線と扉の判定は、間引いた。
- 階のファイルは gzip(840ファイルで約9MB)。

## 8. 【未確定】

- 区画の考え方(層は区画の集まり)を、都市資料に書き足すか。
- 区画の割り当て(ギルドの区画札)を、ゲームの操作にするか(どの層の、どの区画へ潜るかを選ぶ)。
- 他の冒険者のパーティが、同じ区画にいる(NPC)ようにするか。いまは、遺体と、床の跡だけ。
- 区画の広さと、1回の遊びの長さ(1階の掃除に、何分かかるか)の調整。
- 同じ層の階ごとに、魔物を少しずつ強くするか。いまは、同じ層なら同じ強さ。
- Godot の夜は7夜で折り返すので、第7夜→第1夜の境だけ、階段と一画の続きがずれる(49夜ぶんを書き出せば消えるが、データが7倍になる)。
