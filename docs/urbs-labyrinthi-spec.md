# Urbs Labyrinthi 設計と仕様

## 0. この資料について

ランダムダンジョン生成ツール「Urbs Labyrinthi」（ラテン語で「迷宮の都市」）が、何をどう決めているかの記録。最初の名前は「斥候地図盤」で、途中で改めた。数字はすべて初版の設計値で、遊んでみて変える前提。

| タグ | 意味 |
|---|---|
| 【未確定】 | まだ決めていない。遊んでから決める |
| 【案】 | 世界設定に足した仮の内容。確定事項ではない |

### 0.1 設計メモ（世界設定と矛盾させないための決め事）

- **夜が変わると通路が変わる。大部屋と階段は残る**: 都市GM資料 §0.1「通路や小部屋は夜ごとに不規則に変わる。階段の出現位置だけは規則に従う」に合わせた。乱数を「基礎の種」と「夜の種」の二本に分けてある（§2.1）
- **吐く夜**: 夜の番号から節を求め、古謡版の息継ぎ（3,1,4,5,6,5,7）が偶数の夜を吐く夜とする（都市GM資料 §6.1）。第三節と第五節の夜。遭遇が増え、手強くなる
- **吐く夜の表示は GM 表示だけ**: 探索表示では、節の名前だけを出す。真の周期は PL に見せない
- **第五層の階段**: 鏡の水廊を GM 表示で見ると、下り階段の部屋に「今夜の水鏡の階段は○号室」と出る。地図そのものには、七つの水鏡の間を再現していない【未確定】
- **第10層以降**: 世界設定で決まっていないので、舞台名に「未踏・仮」と付け、中身はすべて仮とした
- **物語の種**: PL資料に載っている制度や噂（潜行許可証、相棒契約、封鎖令、燐晶税、灯守、七芒星の落書き）を、遺留品や痕跡の形で置いた。真相 A/B/C や未確定事項を決めてしまう内容は入れていない。全部【案】
- **魔物の対応**: 層の魔物と SRD の魔物の対応は、置き換えの【案】（データ資料 §7）

## 1. できること

| 機能 | 内容 |
|---|---|
| 生成 | 部屋、通路、扉（開口・扉・施錠・隠し）、罠、遭遇、宝、目印、物語の種を、種と夜から決める。同じ入力なら同じ迷宮 |
| 霧 | まだ見ていないところは霧。見たことがあるところは薄暗く残り、いま見えているところだけ明るい |
| 探索 | 現在地の駒を動かす。扉は入ると開く。罠は気づくか、踏むかする。魔物は視界に入ると現れる |
| 層の移動 | 階段で、上の層・下の層・地上へ移る。通った層は控えてあり、戻ると探索の跡が残っている。層の番号で舞台が切り替わる（1〜2 腐葉の回廊、3〜4 錆鉄の坑道、5〜6 鏡の水廊、7〜9 骨の大聖堂、10〜 未踏・仮） |
| 帳面 | 場所をクリックすると、広さ、出入口、描写、遭遇（能力値つき）、罠（判定と難易度つき）、宝、物語の種が出る |
| 読み上げ | 描写と、Claude に書かせた文を、端末の音声合成で読む。自動GMの応答は、語りの部分だけを読む |
| プロンプト | 選んだ場所や階層全体について、Claude に書かせるためのプロンプトを組む。公開ページでは、その場で書かせることもできる |
| 書き出し | 部屋、扉、罠、遭遇、壁の線分を JSON で出す。地図の下絵を PNG で出す（1マス50ピクセル。霧、駒、扉は描かない。未発見の隠し扉は壁として描く） |

**表示の切り替え**

| 表示 | 見えるもの |
|---|---|
| 探索（霧あり） | 駒が見た範囲だけ。未発見の罠、隠し扉、宝、物語の種、吐く夜かどうかは出ない |
| GM（全表示） | すべて。未発見のものには「未発見」と付く。駒がまだ見ていない範囲は、うっすら暗い |

**操作**

- クリックで場所を選ぶ。同じ場所をもう一度クリックするか Enter で、そこまで歩く
- 階段のある部屋の帳面に「階段」の欄が出る。上り階段では「上へ行く」（第1層では「地上へ戻る」）、下り階段では「下へ行く」。探索表示では、その部屋まで歩くと押せる。階段のマスに乗ると、帳面が開く
- 地図にフォーカスを置いて、矢印キーか WASD で一歩ずつ進む
- 歩いている途中で、新しい部屋に入る、魔物が見える、罠に気づく、罠を踏む、のどれかが起きると止まる
- 発見ずみの罠は、経路が避ける。一本道なら、帳面で「解除した」か「発動した」を押して先へ進む

## 2. 生成の手順

### 2.1 種

| 乱数 | 種の文字列 | 決めるもの |
|---|---|---|
| 基礎の種 | `種｜舞台｜広さ｜base` | 大部屋の位置と形、大部屋の名前、上り階段と下り階段の部屋 |
| 夜の種 | `種｜舞台｜広さ｜night｜夜` | 小部屋、通路、扉、罠、遭遇、宝、目印、物語の種、灯りの有無 |

舞台の最初の層（1、3、5、7、10）以外では、どちらの文字列にも末尾に `｜f層` が付く。同じ舞台でも、層が違えば別の地図になる。最初の層は、層を指定しないときと同じ地図。

乱数は xmur3（文字列のハッシュ）と mulberry32。`Math.random` は使っていない（ダメージを振るボタンと、種の振り直しだけ例外）。

### 2.2 部屋

| 項目 | 小 | 中 | 大 |
|---|---|---|---|
| 地図（マス） | 40×28 | 56×38 | 72×50 |
| 大部屋の数（目標） | 5 | 10 | 17 |
| 小部屋の数（目標） | 3 | 5 | 9 |

- 1マスは5フィート
- 大部屋は 6〜11 × 5〜9マス、小部屋は 3〜5 × 3〜5マス
- 部屋どうしは、3マス以上あける。通路が部屋のすき間を通れる幅
- 形は三種。舞台ごとに出やすさが違う

| 形 | 作り方 |
|---|---|
| 四角 | 枠いっぱい |
| 円形 | 枠に内接する楕円 |
| 不定形の洞 | 枠の中をランダムに埋め、セル・オートマトン（まわり9マス中5マス以上が床なら床）を3回かけ、いちばん大きい塊だけ残す。枠の45%に満たなければ四角にする |

| 舞台 | 四角 | 円形 | 洞 | 通路の曲がりやすさ |
|---|---|---|---|---|
| 腐葉の回廊 | 25% | 15% | 60% | 0.7 |
| 錆鉄の坑道 | 70% | 10% | 20% | 0.15 |
| 鏡の水廊 | 35% | 45% | 20% | 0.3 |
| 骨の大聖堂 | 50% | 40% | 10% | 0.1 |
| 第10層以降（仮） | 20% | 50% | 30% | 0.4 |
| 汎用ダンジョン | 70% | 15% | 15% | 0.1 |

### 2.3 つなぎ方

1. 部屋の中心どうしの距離で、最小全域木を作る（プリム法）。これで全部屋がつながる
2. 各部屋について、近い順に3部屋を見て、まだつながっていなければ 22% で枝を足す。これが環になる道

### 2.4 通路

部屋の中心から相手の部屋まで、A* で掘る。状態に進行方向を含め、曲がるたびに罰をつける。

| マス | コスト |
|---|---|
| 出発・到着の部屋の中 | 1 |
| すでに掘った通路 | 1（合流しやすくする） |
| 岩 | 3 ＋ ノイズ × 曲がりやすさ × 4 |
| 出発・到着の部屋のまわり1マス | 岩のコスト ＋ 9（壁沿いに這わせない） |
| 隣に別の通路がある岩 | 1本につき ＋1.5（二重通路を避ける） |
| 方向転換 | ＋1.2 |
| ほかの部屋と、そのまわり1マス | 通れない |

- 木の枝を先に掘り、環の枝をあとから掘る
- 行き止まりの枝道を、小1本・中2本・大3本まで足す（長さ3〜6マス）。半分の確率で、先端に罠を置く

### 2.5 扉

通路が部屋に入る最初のマスを候補にする。両脇が岩で、前後が通れるときだけ扉にする。

| 枝 | 開口 | 扉 | 施錠 | 隠し |
|---|---|---|---|---|
| 木の枝 | 38% | 62% | — | — |
| 環の枝 | 20% | 40% | 22% | 18% |

- 施錠の解錠難易度は 10, 12, 15, 15, 18 のどれか。隠し扉の発見難易度は 12, 13, 15, 15, 17 のどれか
- 最後に、施錠と隠し扉を通らずに全部屋へ行けるかを確かめる。行けなければ、行く手をふさぐ扉を普通の扉に戻す。**鍵や発見に失敗しても、詰まない**

### 2.6 階段

- 上り階段は、左上寄りの大部屋3つのうち一つ
- 下り階段は、上り階段からいちばん遠い大部屋
- どちらも基礎の種で決まり、夜が変わっても動かない
- 降りると次の層の上り階段に、上がると前の層の下り階段に着く。上の層の下り階段と、下の層の上り階段の位置は、そろえていない
- 層を移っても、パーティのレベルと夜は変えない。種、夜、人数などの設定を変えると、通った層の控えは消える

### 2.7 検証した範囲

6舞台 × 3サイズ × 2版 × 25種 ＝ 900通りを生成し、全部屋の連結、同じ入力での再現、扉の両脇が岩であること、魔物の駒が床にあることを確かめた。失敗は 0件。1枚の生成は、3サイズの平均で約7ミリ秒。

## 3. 中身の決め方

### 3.1 部屋

入口の部屋には何も置かない。ほかの部屋は、次のどれか一つ。

| 中身 | 静かな夜 | 吐く夜 |
|---|---|---|
| 遭遇 | 40% | 58% |
| 罠だけ | 10% | 10% |
| 宝だけ | 8% | 8% |
| 目印 | 20% | 20% |
| 何もない | 22% | 4% |

- 下り階段の部屋は別扱い。70% で「階段の番」（難度・高）、30% で目印
- 上に加えて、どの部屋にも 12% で罠が一つ付く
- 物語の種は、34% の部屋に一つ
- 遭遇のある部屋の 50%（階段の番は 90%）に宝
- 大部屋には、舞台ごとの確率で灯りがある（腐葉の回廊 40%、錆鉄の坑道 15%、汎用 20%、ほかは 0%）。灯りのある部屋は、入った時点で全体が見える

### 3.2 遭遇

1. 難度を選ぶ。静かな夜は 低50 / 中36 / 高14、吐く夜は 低35 / 中40 / 高25
2. 予算 ＝ 一人あたりの XP 予算 × 人数（データ資料 §8.1）
3. 舞台の候補から、主になる魔物を一種選ぶ。予算の2割以上を占める魔物が選ばれやすい
4. 数 ＝ 予算 ÷ XP（上限は 8体。大型以上は 3体、群れは 3つ、伝説的な魔物は 1体）
5. 3体以上なら、40% で半分を同じ種別の弱い魔物に入れ替える
6. 合計 XP から難度の札を付ける（ごく低・低・中・高・危険）

**候補の重み**

- 舞台ごとに、種別の重みを持つ（例: 骨の大聖堂は 不死5、人造2、魔族1.5、異形1、怪物0.7、天界種0.3）
- 層の魔物（洞窟鼠など）に対応する SRD の魔物は、重みを6倍にする
- 野獣、人型、精霊は、舞台に合う名前のものだけ通す（錆鉄の坑道の人型は、bandit、thug、scout など。闇潜りや盗掘者に見立てる）
- 泳ぐことしかできない魔物は、鏡の水廊にだけ出る。鏡の水廊では、泳げる魔物の重みを1.6倍にする
- 脅威度がレベル＋3を超える魔物は出ない。レベルの1/8に満たない魔物は、重みを1/4にする
- 部屋の広さに合わない大きさの魔物は出ない（大型は20マス以上、超大型は48マス以上、巨大は80マス以上）

**様子と態度**

| 種類 | 様子の例 | 態度 |
|---|---|---|
| 不死、粘体、人造、植物 | 動かずに立っている、同じ場所を巡っている | 敵対 |
| 野獣、群れ、知力4以下 | 餌をあさっている、巣で休んでいる | 敵対 2/3、警戒 1/3 |
| それ以外 | 待ち伏せている、言い争っている、野営している | 敵対 1/2、警戒 1/4、交渉の余地あり 1/4 |

**通路の魔物**: 入口から12マス以上離れた通路に、0〜2組（吐く夜は＋1組）。予算は人数の6割で、難度は低。

### 3.3 罠

- 通路の罠は、通路のマス数 ÷ 70 個ほど
- 危険度は 軽度60 / 危険32 / 致命的8。セーヴ難易度、攻撃ボーナス、ダメージは SRD 5.1 の表から（データ資料 §8.2）
- 気づく難易度 ＝ 10 ＋ 危険度の段階 × 3 ＋ 0〜2。解除の難易度 ＝ 気づく難易度 − 1〜＋2
- 駒から2マス以内で、視界に入っていて、受動〈知覚〉が難易度以上なら、自動で気づく。隠し扉も同じ
- 罠の種類は、舞台ごとに 4〜7種

| 舞台 | 罠 |
|---|---|
| 腐葉の回廊 | 腐れ床の落とし穴、胞子溜まり、叫び茸の輪、根に吊られた天井、滑る苔の斜面 |
| 錆鉄の坑道 | 朽ちた支保工、暴走する鉱車、錆びた落とし格子、鉱毒の噴気、立坑の蓋、仕掛け弩 |
| 鏡の水廊 | 沈む渡し石、満ちる水門、鏡の眩惑、水鏡の引き込み、冷たい霧の噴き口、毒の吹き矢 |
| 骨の大聖堂 | 骨の槍衾、嘆きの共鳴、崩れる骨のアーチ、祭壇の冷気、閉じる歯列、落ちる吊り香炉 |
| 第10層以降（仮） | 床の口、逆さの重み、名を呼ぶ声、濃い光の溜まり |
| 汎用 | 落とし穴、槍付きの落とし穴、崩れる天井、毒矢、落ちる網、転がる岩、火を噴く像 |

### 3.4 宝

- ヴェルガの層では、燐晶の原石。重さ ＝ 0.2〜1.5kg ×（レベル帯 ＋ 1）。階段の番の部屋は2倍
- 見積もり ＝ 重さ × 1kg あたりの銀貨（純度 低30、並50、高80、極140）。精錬品が 80銀貨/kg という都市GM資料 §14.1 を目安にした設計値【未確定】
- 35% で、遺品、道具、治療薬、灯具のどれかが付く
- 汎用ダンジョンでは、20〜120gp × レベル
- 広さは、小(40×28)、中(56×38)、大(72×50)、特大 XL(96×64)、広大 XXL(128×86)。Godot 版は、上の層ほど広い(docs/dungeon-scale.md)
- Godot 版では、宝箱は使わず、燐晶は床に落ちている光る石(純度 低・並・高・極・不明)。茸などの自生物は、燐晶ではないので税がかからない(docs/items-and-forage.md)

## 4. 霧と視界

- 視界は、再帰シャドウキャスティング（8方向）。半径は「灯り」の欄のマス数（初期値6＝30フィート）
- 岩、閉じた扉、未発見の隠し扉が、視線を遮る
- マスごとに「見たことがある」「いま見えている」の二つを持つ
- 描画は、地図と同じマス数の小さな画像に霧の濃さを書き、引き伸ばして重ねる。境目がぼける
- 魔物は、いま見えているマスにいるものだけ描く。扉、階段、気づいた罠は、見たことがあれば薄く残る

## 5. 書き出す JSON（urbs-labyrinthi/0.1）

座標はマス単位で、左上が (0,0)。壁の線分だけ、マスの角（格子点）の座標。

| キー | 中身 |
|---|---|
| `schema` | `urbs-labyrinthi/0.1` |
| `meta` | `seed`、`theme`、`theme_name`、`floor`（層）、`night`、`setsu`（節）、`exhale`（吐く夜か）、`size`、`grid`（幅、高さ、1マス5フィート、画像の1マスの画素数）、`party`（人数、レベル）、`rules`（SRD の版） |
| `legend` / `grid` | 行ごとの文字列。`#` 岩、`.` 部屋、`,` 通路、`+` 扉 |
| `rooms[]` | `id`、`no`（表示番号）、`name`、`role`（entrance / exit / room）、`big`、`shape`、`x` `y` `w` `h`、`center`、`area_cells`、`lit`、`exits[]`（方角、種類、扉の id）、`flavor`、`feature`、`hook`、`treasure`、`encounter`（id）、`traps[]`（id） |
| `doors[]` | `id`、`x` `y`、`axis`（ew＝東西に通り抜ける / ns）、`type`（door / locked / secret）、`lock_dc`、`find_dc`、`roomId` |
| `stairs` | `up` と `down`。それぞれ `x` `y` `room` |
| `traps[]` | `id`、`x` `y`、`roomId`（通路は −1）、`name`、`severity`、`trigger`、`kind`（save / attack / alarm）、`save`（能力、難易度）、`attack_bonus`、`damage`、`damage_type`、`half_on_success`、`effect`、`detect_dc`、`disarm_dc`、`state` |
| `encounters[]` | `id`、`roomId`（通路は −1）、`boss`、`xp`、`difficulty`、`activity`、`attitude`、`kind`（mindless / beast / smart。魔物の頭の種類）、`monsters[]`（SRD の index、英語名、日本語名、世界での呼び名、数、能力値一式）、`tokens[]`（駒の位置と、どの魔物か） |
| `walls[]` | `[x0, y0, x1, y1, 種類]`。種類は wall / door / locked / secret。同じ向きに続く壁は、一本にまとめてある |
| `license` | 魔物データの帰属 |

- 中サイズで、壁の線分は約160本、JSON は約18KB
- 探索の進み具合（どこを見たか、どの扉を開けたか）は、書き出さない【未確定】

## 6. Claude 用プロンプト

### 6.1 種類

| 名前 | 対象 | 表示 | 書かせるもの |
|---|---|---|---|
| 読み上げ描写 | 場所 | 探索・GM | 踏み込んだ瞬間に読み上げる 120〜200字。未発見のものは、データごと渡さない |
| 遭遇の演出と戦術 | 場所 | GM | 気づく前の様子、第1ラウンド、地形の使い方、逃げる条件、戦わずに済む道 |
| 罠の描写と裁定 | 場所 | GM | 手がかり三つ、発動の描写、解除の手順二通り、発動後の変化 |
| 物語の断片 | 場所 | GM | ここで何があったか、見つけられる手がかり三つ、街で誰が関心を持つか |
| 自動GMの応答（JSON） | 場所 | 探索・GM | GM なし進行用。§6.3 |
| 斥候報告書 | 階層全体 | GM | 地図師が潜行前に渡す報告。罠や宝の位置は、ぼかす |
| 今夜の筋書き | 階層全体 | GM | 導入、山場の部屋二つ、物語の種の結びつけ、締め方 |

### 6.2 組み立て

どのプロンプトも、同じ順で組む。

1. 役割（GM の補佐。データだけを根拠にする）
2. 世界（PL資料の範囲だけ。迷宮都市、燐晶と税、動く通路と呼吸、許可証の等級、いまいる層）
3. 今夜（第何夜、何節の夜、吐く夜か）
4. パーティ（人数、レベル、受動〈知覚〉、光源の半径）
5. データ（生成器の出力を JSON で。魔物は能力値つき）
6. 書くもの（番号つきの注文）
7. 決まり（数値を変えない。データにない固有名詞や魔物を足さず、足したいものは「提案」に分ける。world_name を作中の呼び名にする。文体）

- 真相 A/B/C、古謡、封印簿などの GM 専用設定は、プロンプトに入れていない。入れたいときは、GM がプロンプトに書き足す【未確定】
- 探索表示では、プロンプトの中身を折りたたんである。未発見の情報が入ることがあるため

### 6.3 自動GMの応答の形

GM のいない卓で、進行役の代わりに返す応答。この形を、FVTT の自動進行でもそのまま使う想定（展開メモ §2.4）。

```json
{
  "narration": "プレイヤーに見せる語り。200字まで",
  "checks": [
    { "who": "all | 先頭 | 名前", "ability": "判断力", "skill": "知覚", "dc": 12,
      "on_success": "分かること", "on_failure": "起きること" }
  ],
  "monsters": [
    { "index": "SRDのindex", "intent": "attack | ambush | flee | parley | idle",
      "target": "誰を狙うか", "reason": "一言" }
  ],
  "reveal": ["この応答で明かしてよい事実"],
  "hidden": ["まだ伏せておく事実"],
  "choices": ["プレイヤーに示す選択肢。3つまで"]
}
```

- 画面では、語り・選べること・判定を表に出し、判定の結果、魔物の意図、伏せてあることは、折りたたんで出す
- 直前の探索の記録（最大8件）を「ここまでの経過」として添える

## 7. ファイルの作り

- HTML 1本。外から読むのは、書体（Google Fonts）だけ。読めなくても、端末の書体で動く
- 中に、魔物データ2版（各 約125KB）、生成ロジック、画面のコードが入っている。全体で 約390KB
- **生成ロジックは画面と切り離してある**。HTML の中の `const Core = (() => { … })();` の部分は、ブラウザの機能を使っていない。そのまま Node や FVTT のモジュールへ持ち出せる

| `Core` の関数 | 役目 |
|---|---|
| `generate(opts, monsters)` | 迷宮を一枚作る |
| `computeVisible(D, x, y, 半径)` | 見えるマスを返す |
| `walls(D)` | 壁の線分を返す |
| `exportJSON(D)` | §5 の JSON を返す |
| `buildPrompt(id, D, sel, x)` | §6 のプロンプトを返す |
| `THEMES` | 舞台の定義。部屋名、描写、目印、物語の種、罠、魔物の重みと対応表 |
| `nightInfo(n)` / `mirrorRoom(n)` | 夜の番号から、節と吐く夜／第五層の階段の部屋 |
| `themeForFloor(n)` / `floorLabel(theme, n)` | 層の番号から舞台／層の呼び名（第n層、地下n階） |

- 色と書体は、座環盤に合わせた（Shippori Mincho と Zen Kaku Gothic New、青緑と青銅）
- 公開ページ（アーティファクト）でだけ動く機能が二つある。「この場で書かせる」と、JSON の「ファイルに保存」。単体の HTML では出ない。コピーと、地図の画像の保存は、どちらでも使える

## 8. 分かっている限界

- 魔物は動かない。視界に入っても、駒は止まったまま
- 戦闘の処理はない。帳面に能力値を出すところまで
- 駒は一つ。パーティを一人ずつ動かせない
- 通路は幅1マス。広い通路、段差、水路、橋はない
- 同じ舞台の中の層（第1層と第2層など）は、地図が違うだけ。魔物や罠の決め方は同じ
- 読み上げは、端末に入っている日本語の音声に頼る。公開ページの中で実際に鳴るかは、確かめられていない
- 罠の発動は、踏んだ者だけが対象という前提。範囲は帳面の文で読む
- 扉の鍵、隠し扉の向こうにだけある宝、鍵と錠の組み合わせ、といった仕掛けはない
- 第五層の「七つの水鏡の間」を、地図として作っていない
